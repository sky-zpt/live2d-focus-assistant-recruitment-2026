# 招新考核起始版本说明

本文件只存在于 `issue-preparation` 分支，用于维护者确认“从完整版挖出的缺口”是否真实存在。它不是给考生的 Issue，也不应直接复制到公开考核仓库。

## 分支边界

- `main` 和 `v1.0.0-full` 保留完整、稳定、可运行版本；
- `issue-preparation` 保留同一套前端和 Live2D 资源，只在 Python 后端保留适合新生实现的功能缺口；
- 不故意破坏开始、暂停、继续、完成、放弃和最近完成记录等核心体验；
- 不在此分支创建 GitHub Issue，正式开放时再把本分支复制到考核仓库并创建题目。

## 当前可挖出的真实缺口

以下缺口对应 `docs/python-issue-design.md`，每项都可以独立实现，不要求等待其他同学的代码：

- 历史查询当前固定按完成时间排序，缺少安全的排序白名单和完整筛选元数据；
- 导入导出虽然能处理基础 JSON，但缺少严格版本、字段、数值、时间和重复记录校验，也没有完整事务保护；
- 报告接口目前只有基础计数，缺少日期范围、每日汇总、时段分析、连续天数和可读文本；
- `/api/stats/daily` 与 `/api/stats/time-buckets` 仅保留兼容入口并返回空/零值，具体聚合逻辑对应 M01、M02；
- 异常会话清理只做最小状态转换，未完整结算活动会话已消耗时间，也缺少充分的输入边界处理；
- CLI 历史浏览只展示基础字段，筛选、参数错误提示和摘要格式仍可完善；
- 任务文本规范化、秒数格式化、状态映射、完成率计算、时长分类、摘要生成和查询参数解析尚未抽成独立公共函数。

## 验证要求

维护者应以 `main` 作为行为对照，确认考核分支的缺口是“功能未完成”而不是核心功能崩溃。候选人的 PR 只需完成所认领的一个或多个独立目标；隐藏检查和最终合并在正式考核仓库中维护。
