# Free-play 自由发挥目录

本目录用于本次招新考核的 Free-play 项目。选择 Issue 认领路线的同学不需要修改这里；选择 Free-play 路线的同学，请在此目录中创建自己的独立项目。

## 目录规则

请使用自己的真实姓名创建目录，并只在自己的目录中提交项目。例如姓名为“张三”：

```text
contrib/
└─ 张三/
   ├─ README.md
   ├─ main.py
   └─ 其他确有必要的源码或数据文件
```

- 目录名使用真实姓名；不要使用网名、“最终版”“test”等含义不清的名称。若与已有目录重名，请先联系维护者确认命名方式。
- 一个同学只维护一个自己的目录；可在其中迭代同一个项目，不要修改其他同学的目录。
- 源码、项目 README 和项目专用依赖说明都放在自己的目录中；不要修改 `src/`、`static/`、`templates/`、根目录 `requirements.txt` 或 Live2D 资源。
- 不提交 `.venv/`、`__pycache__/`、`.pytest_cache/`、数据库、账号密码、Cookie、Token、下载缓存或大体积无关文件。

## 项目最低要求

项目必须是可实际运行的 Python 程序，有清晰的输入、处理与输出。它至少应包含循环或条件分支，或者有实际的数据处理逻辑；仅输出固定文字、几行加减乘除或无法操作的演示代码不符合要求。

允许做文字游戏、命令行工具、学习辅助、数据处理小工具等。涉及网站、账号或自动化的项目只能用于你有权访问的系统和数据；不得收集他人凭据、绕过验证/限制，或对第三方服务造成干扰。

## 项目 README（必需）

每个项目必须在自己的目录中提供 `README.md`，至少包含：

1. 项目名称和用途；
2. 实现的主要功能与典型使用流程；
3. 环境要求、安装方式和运行命令；
4. 项目文件说明；
5. 你亲自执行过的手动验证步骤和结果；
6. 已知限制或尚未完成的想法；
7. 参考资料、借鉴链接和 AI 使用说明。

可以查询搜索引擎和使用 AI，但不要直接放入自己看不懂、改不动或讲不出的完整代码。若借鉴了核心思路或代码，请给出链接，并写明你理解了什么、改动了什么。

## 提交要求

- 建议分支名：`feat/contrib-你的真实姓名-简短名称`。
- 提交 PR 时选择模板中的“Free-play 自由发挥”，填写项目目录，不填写 `Closes #编号`。
- 在 PR 中用自己的话解释实现思路、手动验证过程、遇到的问题和参考资料。
- 截止时间为 **2026 年 9 月 27 日 12:00（北京时间）**，以 GitHub 上显示的 PR 创建时间为准。

维护者会关注代码是否可运行、项目是否完整、你能否清楚讲述自己的思路，以及你面对问题时如何检索和解决。
